# CLAUDE.md

Инструкции для Claude Code в этом репозитории (сайт студии красоты The Garden). Читать вместе с `TZ.md`, `PRODUCT.md`, `DESIGN-SYSTEM.md`.

## Экономия на проверках качества

Полная критика (`/impeccable critique` с двумя независимыми субагентами — design review + detector/evidence) стоит дорого и не нужна после каждого маленького шага.

Правило:

- **После каждого шага** из `TZ.md` §11: только `impeccable detect --json src/` и обычный lint/typecheck (`npm run check`, `npm run build`). Без `/impeccable critique`, без субагентов.
- **Полная критика** (`/impeccable critique`, два изолированных субагента, запись в `docs/critique-log.md`) запускается только:
  - после шага 4 (хромовый пион),
  - после шага 7 (прайс),
  - после шага 10 (лояльность/связь/контакты/подвал),
  - в финале (шаг 13).
- Если пользователь явно просит критику на промежуточном шаге — выполнять её, это правило не блокирует прямой запрос.

**Почему:** субагенты для критики расходуют бюджет по токенам/вызовам; большинство промежуточных шагов — это структура и поведение, а не финальная визуальная полировка, которую имеет смысл критиковать дважды.

## Коммиты

Коммит + push после каждого шага §11, независимо от того, был ли запуск полной критики.
